1. What is RDCManagerX?

RDCManagerX is a connection manager for Remote Desktop, similar to Microsoft Remote Desktop Connection Manager (RDCMan). You organise servers in groups, connect with a double-click and work with several sessions in tabs.

  • Works with your existing RDCMan files (.rdg): open them without conversion, and they stay usable in RDCMan.
  • Dynamic resolution: the session adapts to the window or pane, without reconnecting.
  • Reachability in the tree: see at a glance which servers are online, including stale DNS records.
  • Password vault with a master password (AES-256), off by default.
  • Routes via an RD Gateway or a Tailscale network, per server or group.
  • Language: English or Dutch (File > Options); by default the app follows the Windows display language.
  • One exe, no installation.

2. Getting started

Start RDCManagerX.exe. No installation is needed; your administrator puts the exe on a network share or distributes it through a launcher. At startup the files that were open when you last exited are reopened. Everything is collapsed then, except Recent and Favorites.

WhatWhere
App settings (window, recent files, options)%APPDATA%\RDCManagerX\settings.json
Remembered passwords and secretsWindows Credential Manager, encrypted with your master password
Debug log (only with /debuglog)%LOCALAPPDATA%\RDCManagerX\debug.log

You can also open a file from the command line: RDCManagerX.exe path\to\file.rdg.

3. Files

FormatDescription
.rdgThe RDCMan format. RDCManagerX reads and writes it without changing anything RDCMan knows about. RDCManagerX's own settings (display, route, ping, Wake-on-LAN) go into a separate file next to it: <file>.rdg.rdcx.json.
.rdcxOwn format (JSON) with everything in one file. The default for a new file.
  • You can have several files open at once, for example "Work" and "Private"; each file is its own node in the tree.
  • Save as converts a file between .rdg and .rdcx.
  • A * after the file name means: unsaved changes. Automatic saving can be turned on in Options.
  • Passwords are never stored in a file. Passwords in an RDCMan .rdg are ignored when the file is opened.

4. The tree

On the left is the tree with files, groups and servers, sorted alphabetically with groups first. At the top are Recent (last connected servers, newest first) and Favorites (via Server > Add to favorites).

Server colours

IconMeaning

GreenNo session; reachable
RedNo session; not reachable
OrangeReachable, but a different computer answers at that address: the DNS record is probably stale

Selecting a server that has an open tab shows that tab. Move servers and groups by dragging them.

5. Search

Press Ctrl+F (or click the search box above the tree) and type part of the name. The tree then shows only servers whose display name or host name matches, with their groups above them; everything is expanded. Clear the search box (or press Esc) to see everything again. Ideal in large files.

6. Connecting and sessions

  • Connect: double-click a server, or select it and press Enter. If it already has a tab, that tab is shown.
  • A whole group: Server > Connect all servers. The credentials are asked only once.
  • Disconnect: Ctrl+D or via the menu. The session on the server keeps running; the tab closes.
  • Tabs: right-click a tab for Reconnect, Disconnect, In a separate window, Full screen, Scale and Move to next pane. Middle-click closes a tab.
  • Split view (View menu): 2 side by side or stacked, 3 or 4 side by side, 2×2, 3×2, 4×2 or a custom layout (up to 6 columns × 3 rows). Each pane has its own tabs; each session follows the size of its pane.
  • Dragging tabs: within a tab bar to change the order, or to another pane to show the session there.
  • Detach: a session in a separate window or full screen; closing that window puts the session back.
  • Exiting with open sessions asks for confirmation first.
If a connection drops because of a network problem, the RDP client tries to reconnect by itself. If that fails, the tab stays open with the message; choose Reconnect then.

7. Display and scale

By default RDCManagerX uses dynamic resolution: the resolution of the session follows the size of the pane or window, without reconnecting. The scale (100% to 300%, or automatic according to your monitor) is set per server or group (Properties > Display) or temporarily per tab (right-click > Scale).

Other display modes (Properties > Display): Window size at connect, Fixed size and Full screen. If an older server does not support dynamic resolution, RDCManagerX can optionally reconnect with the new size.

8. Properties and inheritance

Right-click a file, group or server > Properties (Alt+Enter).

TabContents
GeneralName, host name, comment; for servers also Wake-on-LAN
LogonUser and domain, or a credential profile of the file
ConnectionPort, administrative session (console), start program, load balancing
RouteDirect, via RD Gateway or via Tailscale; reachability (ping)
DisplayDisplay mode, scale, fixed size, colour depth
Local resourcesClipboard, drives, printers, sound, smart cards, Windows key combinations
SecurityServer authentication (certificate check)

Inheritance: each tab has the checkbox Inherit from parent group at the top (for a file: from default settings). A setting on a group or on the file itself applies to everything below it, unless a group or server has its own setting. That way you set, for example, the user name or the ping once for a whole group.

9. Logon and password vault

RDCManagerX asks for the password at every connection, unless it is remembered. Remembering is only possible when File > Options > Allow remembering passwords is on; it is off by default.

  • When you turn it on you set a master password (at least 10 characters). Remembered passwords are encrypted with it (AES-256, key derived with PBKDF2) and additionally protected by Windows.
  • The Remember password checkbox in the logon prompt is never ticked by itself.
  • The vault locks after a configurable number of minutes without use (Options). Manually: File > Lock password vault.
  • Change the master password: File > Change master password or the button in Options.
  • If the server rejects a remembered password, it is forgotten automatically. Manually: Server > Forget remembered password.
  • Credential profiles (File > Credential profiles): shared user names per file, as in RDCMan.
Forgot your master password? It cannot be recovered. The vault can only be emptied; after that you set a new master password.

10. Route: direct, gateway, Tailscale

On the Route tab you choose how a server is reached:

RouteDescription
DirectDirectly, optionally via the RDCMan gateway setting on the same tab (stored in the .rdg).
Via RDP gatewayA gateway from File > RDP gateways: server, port, usage method and credentials. The gateway password can be stored in the vault. Not tested yet against a real RD Gateway.
Via Tailscale networkA network from File > Tailscale networks. RDCManagerX itself temporarily becomes a device in the tailnet; Tailscale does not need to be installed on this PC. In Address in the tailnet enter the machine name or the 100.x address.

Networks and gateways belong to the file; auth keys and passwords are stored only in the vault on your own PC. Via Tailscale a certificate warning appears (name 127.0.0.2); the connection itself is encrypted by Tailscale.

Tailscale only with an ACL. Tailscale's default policy allows everything: every device in the tailnet may reach every other device. So set up an ACL in the Tailscale admin console (Access controls) that allows RDP (TCP 3389) only from the RDCManagerX node (tag:rdpclient) to the target PCs (tag:rdpserver), and remove the allow-all rule. Also turn on MFA and device approval. The example is in README.md.

11. Reachability (ping)

Turn on for a file, group or server: Properties > Route > Show reachability in the tree (clear the inherit checkbox first). RDCManagerX then checks those servers in the background:

  1. a ping; if there is no reply, a short connection to the RDP port (Windows often blocks ping);
  2. if the server is reachable, NetBIOS is used to check that the expected computer really is at that address.

You see the result in the colour in the tree (see The tree) and in the status bar for a selected server, e.g. "dc01 is online (3 ms)". The interval (30 seconds by default) is set in Options. Only servers with route Direct are checked; several at once, without slowing down the app.

Orange usually means a stale DNS record: the address was handed out by DHCP to another device, but the old record is still in DNS. Solution: enable DNS scavenging and delete the old record (see Troubleshooting).

12. Wake-on-LAN

Enter the MAC address for a server (Properties > General), optionally with broadcast address and port. Then wake the computer with Server > Send Wake-on-LAN packet.

13. Options

File > Options:

  • Language: System, English or Dutch (applies at the next start)
  • Number of servers in Recent
  • Theme: System, Light or Dark (also via View > Theme; applies at the next start if sessions are open)
  • Automatic saving
  • Allow remembering passwords, automatic locking, change master password
  • Interval of the reachability check

Settings are only saved if they were changed in that session; two open windows therefore do not overwrite each other's settings.

15. Troubleshooting

Debug log

Start with RDCManagerX.exe /debuglog and look at %LOCALAPPDATA%\RDCManagerX\debug.log. Passwords never go into the log.

Server orange in the tree (wrong computer)

Check with:

nslookup <name>          (which address does DNS return?)
nbtstat -A <ip-address>  (which computer is really there?)

Delete the stale record on a domain controller and enable DNS scavenging (aging on the zone, scavenging on the server), matched to the DHCP lease time:

Remove-DnsServerResourceRecord -ZoneName contoso.local -RRType A -Name <name> -RecordData <ip>
Set-DnsServerZoneAging -Name contoso.local -Aging $true -NoRefreshInterval 3.00:00:00 -RefreshInterval 3.00:00:00
Set-DnsServerScavenging -ScavengingState $true -ScavengingInterval 1.00:00:00 -ApplyOnAllZones

Password is not remembered / vault asks nothing

Check that Allow remembering passwords is on in Options. If you no longer know the master password, the vault can only be emptied.

Tailscale

  • Tailscale must be running on the target PC, and the firewall must allow RDP (TCP 3389) from 100.64.0.0/10 on the adapter Tailscale.
  • Connecting fails since you set up the ACL? Check that the target PC has the tag tag:rdpserver and the auth key the tag tag:rdpclient.
  • In Address in the tailnet enter the machine name or the 100.x address, not the account's e-mail address.
  • Test connection in File > Tailscale networks shows whether the network starts.

Dynamic resolution does not work right after logon

Some servers need a moment after logon; RDCManagerX keeps retrying for about 25 seconds.
